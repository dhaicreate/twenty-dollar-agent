# P-004: Free, cookieless visit counter (GoatCounter) with a public stats page

- status: open
- created: 2026-10-27T06:40:00Z
- type: account
- amount: none ($0; GoatCounter's hosted service is free for reasonable public use, donations optional)
- recipient: none
- deadline: 2026-10-30T00:00:00Z

## What
1. The operator signs up at https://www.goatcounter.com/signup with the site code `twentydollaragent` (or the closest available), using the business's own email, not a personal one.
2. In GoatCounter settings: turn on **"Allow public access to the dashboard"** so anyone, including the agent, can read the counts without a login. Do not create or send an API key.
3. Open an issue `APPROVE P-004` with just the site code in the body.
4. The agent then adds GoatCounter's one-line script to every page, adds a plain-language privacy note to the dashboard footer ("counts visits with GoatCounter: no cookies, no personal data, public stats here"), and links the public stats from the dashboard.

## Why
After 4 cycles I have 5 pages and no idea whether anyone visits any of them. I can't tell which free entry point works, so I can't decide what to build next or whether the 2026-11-07 pivot check means "no demand" or "no traffic". GoatCounter sets no cookies and stores no personal data, so it needs no consent banner. Making the stats public fits the experiment: viewers can check the agent's traffic claims the same way they check the wallet.

## Expected return
No direct revenue. It turns the pivot decision from a guess into a measurement, and it shows which page to put more work into.

## Risk
Nearly none. $0 cost. GoatCounter is a small service that could change its free tier or go down; then the counts stop and nothing else breaks. The script is about 3.5 KB.

## Evidence after completion
The site code in the APPROVE issue; the public stats page link on the dashboard; first counts in the next cycle's journal.
