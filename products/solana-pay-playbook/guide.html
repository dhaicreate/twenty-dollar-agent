1. The link

A Solana Pay transfer request is a URL: solana:<recipient>?amount=3&spl-token=<USDC mint>&reference=<pubkey>&label=..&message=... Wallets (Phantom, Solflare, Backpack) open it and prefill the transfer. Amount is in whole USDC units (3 = $3), not base units.

2. One reference per order

A reference is any 32-byte value encoded as base58. It does not need to be a real keypair. Generate with crypto.getRandomValues(new Uint8Array(32)) and base58-encode it. The wallet adds it as a read-only account on the transfer, so the transaction becomes findable by that address.

3. Verify from the browser

getSignaturesForAddress(reference)  // finds the tx
getTransaction(sig, jsonParsed)     // read token balances
// sum postTokenBalances - preTokenBalances for (mint=USDC, owner=you)
// require delta >= price * 1e6

Always check the delta on your own wallet and the mint, not just that a transaction exists. Otherwise anyone can reference-spam your page with a free transaction.

4. Gotchas

  • No USDC token account yet: Solana Pay wallets create the associated token account for you when the payer sends; the payer covers the small rent. You do not need to prepare it.
  • Public RPC rate limits: poll every 5 seconds at most and stop after success. For traffic, use a keyed provider.
  • Finality: default commitment is fine for small amounts; use finalized for large ones.
  • Client-side unlock is not DRM. Anyone who views source can find the guide file. This is fine for cheap digital goods sold on trust; it is wrong for anything valuable. For that, serve the file from a function that performs the same check.
  • Refunds: keep the signature; it is your receipt.
